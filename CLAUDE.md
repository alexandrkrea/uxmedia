# UXM.BY: памятка для работы с проектом

Этот файл Claude Code читает сам при открытии папки проекта. Здесь всё, что нужно, чтобы продолжить работу в новой сессии. Для людей: [docs/EDIT.md](docs/EDIT.md) (как редактировать), [docs/CONTENT.md](docs/CONTENT.md) (как заполнять сайт), [docs/PROCESS.md](docs/PROCESS.md) (как мы работали и почему так).

## Как начать в новой сессии

1. Открыть в Claude Code папку проекта (ту, где лежит этот файл). Папку можно переносить куда угодно.
2. Сказать, например: «работаем дальше над сайтом». Прошлую переписку Claude не помнит, всё важное записано здесь и в `docs/`.
3. Если нет папки `node_modules` (после переноса или клонирования), сначала выполнить `npm install`.
4. Сервер для просмотра настроен: `.claude/launch.json`, конфигурация `astro-dev` (порт 5173). Сайт: http://localhost:5173/, админка: http://localhost:5173/keystatic/
5. Перед правками прочитать «Текущее состояние» ниже и `git log --oneline -15`: там видно, что уже сделано.

## Что это

Новостной сайт на русском языке «UXM.BY» (название правится в админке). Сделан по макету Figma (fileKey `wqsGKy6qk0djRcffOB1nOl`, главная node 338:1705, статья 355:4077). Astro 7 (статический вывод) + MDX + админка Keystatic (работает только локально, `npm run dev`).

- Репозиторий: https://github.com/alexandrkrea/uxmedia (публичный, ветка `main`)
- Тестовый стенд: https://alexandrkrea.github.io/uxmedia/ (GitHub Pages, пересобирается после каждого пуша в `main`)
- Сайт закрыт от индексации: `robots.txt` с `Disallow: /` и `noindex` на всех страницах, пока не собрано с `INDEXABLE=true`. Открывать только по прямой просьбе владельца.
- Тексты новостей демонстрационные: факты придуманы, цитаты подписаны «Автор материала». Перед запуском заменить.

## Что умеет сайт (чтобы не ломать)

- Адаптив от 320px до 2560px+, брейкпоинты 640 / 960 / 1100 / 1600 (описаны в `src/styles/00-tokens.css`). Светлая и тёмная темы.
- Режим «молния» (экономия трафика): картинки качества 5 вместо 40, зерно поверх, на телефоне включён по умолчанию (`images.js`, `lite.js`).
- Поиск в стиле Spotlight (Ctrl+K), данные из `search-data.json`.
- Пагинация без перезагрузки со скелетоном (`pager.js`), настоящие адреса `/news/page/N/`.
- Галерея с зумом на весь экран (`gallery.js`, `Lightbox`).
- Страницы: главная, архив, статья, тег, раздел, итоги недели, «О проекте», 404. Всё для SEO и нейросетей: JSON-LD, sitemap, RSS, `llms.txt`, один h1, крошки без текущей страницы.
- Доступность: фокус с клавиатуры, `inert` у фона при открытом поиске, меню и просмотре, ссылка «к содержимому».

## Команды

```bash
npm install    # один раз
npm run dev    # сайт и админка на :5173
npm run build  # сборка в dist
npm test       # сборка + 11 автотестов (проверка dist)
```

Node 22.23+ (проверено на 24). Запуск тестов на GitHub: `.github/workflows/deploy.yml` (сборка, тесты, публикация на Pages с `BASE_PATH=/uxmedia/`).

## Правила работы с владельцем

- Общаться по-русски, коротко, по делу.
- Коммитить и пушить только по прямой просьбе («пуш»). Перед пушем всегда `npm test`. Сообщение коммита заканчивать строкой `Co-Authored-By` по инструкции сессии.
- Не вводить пароли и токены. `gh` не установлен: репозиторий создаёт владелец, пуш идёт из его git-сессии.
- Изменения проверять в браузере цифрами (`getBoundingClientRect`, computed style), а не «на глаз». Для просмотра: `preview_start` (`astro-dev`), потом `navigate`.
- Скриншоты владельца важнее проверки Claude: сверять ширину окна и кеш.
- Каждый раз после правки говорить, что сделано локально, а что отправлено на GitHub.
- Правки в админке владелец делает сам. Файлы `src/content/**` могут меняться без Claude (например, название сайта): не откатывать, а читать текущее состояние.

## Что редактируется в админке

| Раздел | Что внутри |

| Новости | заголовок, адрес, лид, даты, раздел, теги, обложка, «Коротко и по делу», «Баннер справа» (вручную), «Баннер по умолчанию» (галочка), черновик, текст |
| Теги | название, адрес, описание |
| Главная | заголовок, вступление, закреплённая новость, показывать ли баннер, баннеры (можно несколько) |
| О проекте | заголовок, лид, «Коротко», текст |

Остаётся в коде: восемь разделов меню (`SECTIONS`), страница «Итоги недели» (`DIGESTS`, тексты в `digest/[slug].astro`), меню-ссылки «контакты/реклама/о проекте/предложить новость».

## Как устроены баннеры справа (от 1600px)

- Статья: «Баннер справа» вручную, иначе автоподбор (общие теги ×3 и раздел ×2, при равенстве свежая; без самой статьи и материалов «Читайте также»), иначе новость с галочкой «Баннер по умолчанию» (она необязательна), иначе самая свежая другая.
- Главная, архив, «О проекте», итоги недели: баннеры с «Главной» в админке, иначе «по умолчанию»; можно отключить совсем.
- Новость, показанная баннером на главной, в ленту не попадает.

## Подводные камни (на них уже наступали)

- **Keystatic и картинки.** Он ждёт файлы в папке статьи: `src/assets/news/<slug>/файл`, путь в тексте `../../assets/news/<slug>/...`. При Save переименовывает обложку в `image.jpg` и переписывает файл в своём формате (кавычки, даты в UTC). Это нормально. Общей кучей файлы класть нельзя: поле «Обложка» будет пустым.
- **Черновики Keystatic** хранятся в браузере и восстанавливаются («Restored draft»). Если форма неожиданно «Unsaved» или с лишним полем, очистить `localStorage` ключи keystatic.
- **Адреса админки без слэша в конце:** `/keystatic/collection/news/item/<slug>`. Главная страница админки с `/keystatic/`. В dev `trailingSlash: 'ignore'`, в сборке `'always'`.
- **Quote и Checks в MDX** писать блочной формой (пустые строки внутри тега), иначе админка падает с «unexpected children».
- **Заголовки в тексте только `##`** (в админке включён только уровень 2).
- **Якоря в «О проекте»:** заголовки «Контакты», «Реклама», «Предложить новость» нельзя переименовывать, на них ведёт боковое меню (`#контакты` и т. д.).
- **backdrop-filter:** писать только без префикса `-webkit-`, иначе минификатор оставляет префиксный вариант и в Chrome размытия нет.
- **Списки в статье:** маркер висит абсолютно слева (`position: absolute`), не flex: во flex жирный текст внутри пункта разъезжается на колонки.
- **Все маркированные списки показываются с галочками**, точечных нет.
- **Шкала отступов в статье:** заголовок → текст 16px, текст → следующий заголовок 40px, «Коротко» и текст 40px. Менять значения вместе, на всех экранах одинаково.
- **Тест `llms.txt`** читает название сайта из `src/content/site/index.json` (его правят в админке): не писать название жёстко.
- **Git Bash** ломает пути вида `/uxmedia/` (нужно `MSYS_NO_PATHCONV=1`), а heredoc с кириллицей и обратными слэшами в Python лучше заменять файлом через инструмент Write.
- **Размытие и скелетон картинок:** `images.js` переключает качество (режим молнии) и снимает скелетон после загрузки; после подмены контента пагинацией вызывается `watchPhs()` для всей страницы (в том числе баннера).
- **Широкие экраны:** блок двух колонок ленты от 2200px закомментирован в `10-layout.css` (на 2560 одна колонка).

## Картинки

Загружать JPG или WebP, шириной 1200–2000px, обложки 16:9. На сборке Astro делает avif и webp шириной 900 (качество 40 и облегчённое 5 для режима молнии), миниатюры 256px и картинку для соцсетей 1200×630. PNG-оригинал на сайт не попадает.

## Что сделать перед запуском

1. `SITE_URL` (настоящий домен) и почта в «Настройках сайта».
2. Заменить демонстрационные тексты и фото.
3. Собрать с `INDEXABLE=true` (снимает `noindex`, открывает `robots.txt`). В `src/pages/robots.txt.ts` решить, пускать ли ИИ-краулеров.
4. Ссылки на соцсети в «Настройках сайта».
5. Подтвердить сайт в Яндекс Вебмастере и Search Console, отправить `sitemap-index.xml`.
6. Если переезжать с GitHub Pages на свой хостинг: `SITE_URL=https://домен npm run build`, залить папку `dist` (без `BASE_PATH` для корня домена).
7. Для правки с любого устройства: Keystatic в режиме GitHub (`storage.kind: 'github'`) и хостинг с сервером (Vercel, Netlify, Cloudflare).

## Безопасность

Статический сайт: сервера и базы нет, админка в интернет не выходит. Главный риск: аккаунт GitHub (включить 2FA). В публичной истории коммитов видна почта `alexandrkrea@gmail.com`; чтобы скрыть, включить «Keep my email addresses private» на GitHub и перенастроить `git config user.email` на noreply-адрес.
